# 开发、部署与运维

## 1. 当前生产架构

生产环境使用两个 Vercel 项目和一个 Aiven MySQL 数据库：

| 组件 | Vercel 项目 | 生产地址 | 职责 |
| --- | --- | --- | --- |
| 前端 | `dazi-projects/japanese-vocabulary-study` | `https://japanese-vocabulary-study.vercel.app` | Vite 静态站点、SPA History 回退、同源 API Rewrite |
| 后端 | `dazi-projects/japanese-vocabulary-api` | `https://japanese-vocabulary-api.vercel.app` | NestJS Node.js Function、认证与业务 API |
| 数据库 | Aiven MySQL | 不公开 | 正式业务数据、管理员和登录会话 |

浏览器只访问前端生产域名。`frontend/vercel.json` 将 `/api/:path*` 重写到后端固定域名，所以登录 Cookie 维持同源。其他路径回退到 `/index.html`，直接刷新 `/login` 等 React 路由不会返回 404。

后端通过 `backend/vercel.json` 把所有 `/api/:path*` 重写到 `api/index.js`。该单一函数入口保留原始 URL，再交给 Nest 路由匹配；不要恢复成只依赖文件 Catch-all 的配置，否则 `/api/auth/login` 等多层路径可能由 Vercel 返回 404。

两个项目的 Vercel SSO Deployment Protection 已按项目所有者授权关闭。业务数据仍由管理员登录、HttpOnly 会话 Cookie、权限守卫和登录限流保护。

## 2. 本地开发与检查

项目固定使用 Node.js 22。首次安装：

```bash
npm ci
npm run install:all
npm run dev
```

本地数据库配置只放在 `backend/.env.local`。任何 `.env*`、数据库备份、`.vercel/` 元数据和令牌都不得提交。

提交或发布前至少执行：

```bash
npm run lint
npm run typecheck
npm run build
```

后端测试在 Windows 可使用单进程模式：

```powershell
cd backend
.\node_modules\.bin\jest.cmd --runInBand
```

根目录 `npm run build` 会构建前端、复制到 `backend/web`，再构建 NestJS，继续支持传统 Node.js 单服务部署；Vercel 前端项目则直接构建 `frontend/`。

## 3. 生产环境变量

后端生产项目至少需要以下变量，Secret 不写入 `vercel.json`：

| 变量 | 要求 |
| --- | --- |
| `DATABASE_URL` | Aiven MySQL 连接地址，Sensitive Secret |
| `INITIAL_ADMIN_USERNAME` | 随机初始管理员用户名，Sensitive Secret |
| `INITIAL_ADMIN_PASSWORD` | 强随机密码，Sensitive Secret |
| `AUTH_COOKIE_NAME` | 当前使用 `jvs_session` |
| `AUTH_SESSION_DAYS` | 当前使用 `30` |
| `ENABLE_SWAGGER` | 生产保持 `false` |
| `TRUST_PROXY_HOPS` | 当前 Vercel 架构使用 `1` |

Vercel 环境不加载本地静态文件服务，也不写文件日志；日志写到标准输出，由 Vercel Logs/Observability 收集。

更新 Secret 时从标准输入传值，避免进入命令历史；占位值不能直接使用：

```powershell
Set-Location backend
Read-Host "新值" | npx vercel env update INITIAL_ADMIN_PASSWORD production --sensitive --yes
```

环境变量更新只影响后续部署，修改后必须重新部署。

## 4. Vercel 发布

后端发布：

```powershell
Set-Location backend
npm run build
npx vercel deploy --prod --yes
```

后端使用东京区域 `hnd1`。`api/index.js`、`api/[...path].js` 对 `mysql2` 的显式加载，以及 `dist/**` 的函数打包配置都不能删除。

前端发布：

```powershell
Set-Location frontend
npm run build
npx vercel deploy --prod --yes
```

发布后至少验证：

- 首页与直接刷新 `/login` 均返回 HTTP 200；
- `/api/health` 返回 `status: ok`；
- `/api/ready` 返回 `status: ready`；
- POST JSON 登录能收到 HttpOnly 会话 Cookie；
- `/api/auth/me` 能读取用户，退出后 Cookie 失效；
- 主要 CRUD、题库、学习和复习流程正常。

不要通过浏览器地址栏测试登录。地址栏发送 GET；登录必须是 `POST /api/auth/login`。

## 5. 数据库迁移

数据库 `synchronize` 必须保持关闭。首次发布或 schema 变化时，人工确认目标数据库和生产 Secret 后单独运行迁移；不得绑定构建、启动或 Vercel 自动部署：

```powershell
$env:NODE_ENV = "production"
npm run db:migrate --prefix backend
```

生产迁移必须提供 `INITIAL_ADMIN_USERNAME` 和 `INITIAL_ADMIN_PASSWORD`，缺失会在连接数据库前中止。执行前必须备份，执行后检查表结构、管理员登录和关键业务数据。

## 6. 管理员凭据轮换

专用脚本会保留用户数据库 ID、检查用户名冲突、写入 bcrypt cost 12 哈希，并撤销该用户所有有效会话。真实密码不得写入命令文件、文档或 Git。

```powershell
$env:NODE_ENV = "production"
$env:CONFIRM_ROTATE_ADMIN = "ROTATE_ADMIN"
$env:OLD_ADMIN_USERNAME = Read-Host "旧管理员用户名"
$env:NEW_ADMIN_USERNAME = Read-Host "新管理员用户名"
$securePassword = Read-Host "新管理员密码" -AsSecureString
$env:NEW_ADMIN_PASSWORD = [System.Net.NetworkCredential]::new('', $securePassword).Password
npm run admin:rotate --prefix backend
Remove-Item Env:NEW_ADMIN_PASSWORD
```

数据库轮换成功后，必须同步更新 Vercel Production 的 `INITIAL_ADMIN_USERNAME` 和 `INITIAL_ADMIN_PASSWORD` Sensitive Secrets，并重新部署后端。最后确认旧账号返回 401、新账号可登录、`/api/auth/me` 正确、测试会话已退出。

只修改 Vercel Secret 不会自动更新数据库；普通部署不会自动运行迁移。

## 7. 备份与恢复

```bash
npm run db:backup
npm run db:restore -- CONFIRM_RESTORE backups/<backup-file>.sql
```

备份使用 `mysqldump` 单事务模式并包含 routines 和 triggers，写到 Git 忽略的 `backend/backups/`。建议每天备份、加密异地复制并保留日/周/月周期。恢复只接受备份目录内文件，至少每季度在隔离数据库演练并核对核心表、管理员登录及题库进度。

## 8. 本地数据库全量覆盖线上

该操作删除线上全部视图、表和数据，只能在项目所有者明确授权后执行：

```bash
npm run db:sync:online -- OVERWRITE_ONLINE
```

执行前确认 `.env.local` 指向本地库、`.env.production` 指向线上库，且不是同一实例。脚本先备份线上库，再恢复未修改的本地 dump。完成后必须逐表比较表清单和精确行数。该命令不能作为备份方式，也不得加入构建、启动、Git Hook 或自动部署。

## 9. 日志、监控与告警

传统长驻环境写入 `logs/jvs-YYYY-MM-DD-NNN.log`，默认保留 30 天，并在可用磁盘低于 10% 时告警。Vercel Function 只写标准输出。HTTP 日志不记录请求体，密码、Token、Cookie 和 Authorization 必须脱敏。

生产至少监控：

- `/api/health` 可用率和响应时间；
- `/api/ready` 数据库连接失败；
- Vercel Function 5xx、超时和冷启动；
- Aiven 连接数、CPU、存储和慢查询；
- 登录失败异常增长；
- 备份任务失败和备份过期。

## 10. 安全与故障排查

生产默认关闭 Swagger，未知 5xx 只返回“服务器内部错误”，详细堆栈只进日志。TypeORM 生产只记录 `error`、`warn`，Vite 生产不发布 source map。

本地开发环境的 Swagger 地址为 `/api/docs`。“健康检查”分组包含 `GET /api/health` 和 `GET /api/ready` 的用途、成功响应及数据库不可用响应。生产只有在受控网络临时设置 `ENABLE_SWAGGER=true` 并重新部署后才生成 Swagger；排查结束后应立即关闭并再次部署。

| 现象 | 检查项 |
| --- | --- |
| `/api/health` 404 | 后端 Rewrite 是否把 `/api/:path*` 指向 `/api`；`api/index.js` 是否存在 |
| `/api/auth/login` 404 | 是否误用 GET；多层路径是否仍交给单一函数入口 |
| Function 缺少 `mysql2` | 函数入口是否显式加载驱动，是否包含 `dist/**` |
| `/api/ready` 503 | `DATABASE_URL`、Aiven TLS、连接权限、连接数与数据库状态 |
| 登录后无会话 | 是否经前端同源 `/api` 请求，Cookie 是否被阻止 |
| SPA 刷新 404 | 前端 Catch-all Rewrite 是否指向 `/index.html` |
| Secret 修改未生效 | 是否配置到 Production 并重新部署 |

生产故障时先保留日志与数据库备份，再决定回滚部署或恢复数据。代码回滚不会自动回滚数据库。
