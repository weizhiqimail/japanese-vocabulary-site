# 日本語言葉勉強产品需求文档

> 文档状态：开发基线
> 更新日期：2026-08-03
> 产品定位：以统一日语知识库为底座，支持词汇整理、集合管理、学习、复习、测试与知识关联的个人学习工具。
> 本期不包含：JLPT、BJT 等考试专项、排名、社区、付费与教师端功能。

## 1. 背景

本项目是从零建立的个人日语语言知识库与学习系统，以在线 MySQL 为唯一业务数据源，不兼容或迁移任何历史页面、接口、数据表和学习记录。

所有学习行为围绕唯一的正式词库展开；来源单词书、自建集合、收藏本和错题本统一使用集合模型。语法、句子、搭配与词汇分别存储并通过 ID 关联，用户可以从集合发起学习、复习和测试。

`files/` 是受保护的原始资料目录，只作为人工核对材料。任何材料进入正式词库前，都必须先整理为规定 CSV、进入非正式词汇审核池，再由用户批准。

## 2. 产品目标

### 2.1 核心目标

1. 建立唯一、可维护、可扩展的核心词库，避免同一词汇在不同功能中重复存储。
2. 用“词汇集合”统一承载单词书、自建清单、收藏本、错题本等场景。
3. 建立完整的学习闭环：未学习 → 已学习 → 多次复习 → 测试反馈 → 错题强化。
4. 建立词汇、语法、句子之间的关联关系，形成可追溯的语言知识网络。
5. 提供适合 PC 和手机的学习界面，并支持按字段显示、隐藏和默记。
6. 提供跨词汇、搭配与句子的统一模糊检索。

### 2.2 成功标准

- 同一个核心词汇可加入多个集合，但只维护一份基础资料。
- 用户可在 3 次操作内从任意集合开始学习、复习或测试。
- 学习次数与复习次数语义明确，历史记录可追溯。
- 测试错题能够自动进入指定错题本，并累计做错次数。
- 搜索一个日语词，可命中词条本身、读音、翻译、搭配和包含该词的句子。
- PC 使用卡片布局，手机使用紧凑列表，核心操作无需横向滚动。

## 3. 产品原则

1. **词库唯一**：词汇只在核心词库中创建一次，其他模块只引用词汇 ID。
2. **集合复用**：单词书、收藏本、错题本本质上都是集合，通过类型和来源区分。
3. **状态与事件分离**：页面显示当前状态，后台保留每次学习、复习、测试事件。
4. **知识关联不复制**：同音词、近义词、反义词等必须关联核心词库中的现有词条。
5. **先保证个人学习效率**：不因考试体系、社交或游戏化功能增加复杂度。

## 4. 用户与典型场景

### 4.1 目标用户

以中文为母语、长期积累日语词汇的个人学习者。用户会从书籍、文章、视频、工作材料和日常阅读中持续收集词汇，希望统一整理，并对难词反复复习。

### 4.2 典型场景

- 将一本书里的词汇汇总成单词书，并分批学习。
- 阅读时快速新增一个词，稍后补充词性、备注、关联词与例句。
- 从收藏本中开启默记，只看日语，点击后显示读音或翻译。
- 对已经学过的词进行多次复习，查看哪些词复习次数最多。
- 从一个集合随机抽取 20 个词，依次完成日语、假名、翻译三类测试。
- 搜索“基づく”，同时看到词条、搭配“～に基づいて”和例句“法律に基づいて罰する。”。


## 6. 核心数据模型

本节描述产品数据语义，不限定具体数据库实现。

### 6.1 词汇 Vocabulary

| 字段          | 必填 | 说明                                                     |
| ------------- | ---- | -------------------------------------------------------- |
| ID            | 是   | 全局唯一标识                                             |
| 日语词汇      | 是   | 如“顧みる”                                               |
| 假名          | 否   | 如“かえりみる”；允许后续补充                             |
| 翻译          | 是   | 单一文本字段；按规定使用 `。` 与 `、` 组织多义和近义译法 |
| 词性          | 否   | 动词、名词、形容词、副词等；允许多选或细分类             |
| 音调/发音信息 | 否   | 建议预留，本系统 可先不做音频                            |
| 备注          | 否   | 使用差异、语感、来源说明等                               |
| 标签          | 否   | 主题、难度、自定义标签                                   |
| 创建/更新时间 | 是   | 用于排序和维护                                           |
| 逻辑删除状态  | 是   | 默认正常；删除只写删除标记、删除时间和删除人/操作来源    |

同形词、同音词或一词多义可能产生重复判断困难。新增时应根据“词汇 + 假名 + 主要词性”提示疑似重复，由用户选择合并、继续新增或取消。

#### 翻译字段格式

- 每个词汇只维护一个翻译字段，不拆成多条翻译记录。
- 不同含义使用日语句号 `。` 分隔，例如：`回顾。反省。顾及`。
- 同一含义下的相近译法使用日语逗号 `、` 分隔，例如：`回顾、回想。反省`。
- 新增和编辑表单应在翻译输入框附近显示上述格式提示。
- 测试时，以 `。` 切分出的每个含义单元均可作为正确语义；展示标准答案时仍显示完整翻译字段。系统生成干扰项前必须排除与任一含义实质相同的选项。

#### 固定词性

词性必须从系统管理的固定选项中选择，不允许自由输入，以免出现“动词、動詞、自动词”等不同写法。本系统 初始词性至少包括：

| 分组        | 固定选项                           |
| ----------- | ---------------------------------- |
| 名词类      | 名词、专有名词、代词、数词         |
| 动词类      | 自動詞（自动词）、他動詞、サ变动词 |
| 形容词类    | い形容词、な形容词                 |
| 修饰/连接类 | 副词、连体词、接续词               |
| 功能词      | 助词、助动词、感叹词               |
| 复合内容    | 惯用语、固定表达                   |
| 兜底        | 其他                               |

词性选项由系统固定配置；如以后确需增加，只能通过受控的数据迁移或管理配置增加，不能由词汇新增表单临时创造。

一个词汇允许关联多个词性。词性定义在数据库固定词性表中只保存一份，代码使用统一枚举引用其稳定代码；词汇通过多对多关联表保存一个或多个词性 ID。新增词汇时词性非必选，默认空；选择后可以逐项移除。全项目禁止散落词性、标签、审核状态、对象类型等魔法字符串，统一从枚举或常量模块引用。

#### 标签与集合

- 本系统 的“标签”用于描述词汇语言属性，例如拟声词、拟态词、书面语、口语、敬语、易混淆、褒义、贬义等。
- 现有 BJT、N1、BJT-外来语应按**词汇集合/来源集合**处理，不再作为 本系统 词汇标签的示例。
- 一个词汇可拥有多个标签；创建和编辑词汇时均可选择已有标签。
- 标签不可在词汇表单中随意创建，新增、改名、启用、停用统一放在“管理 > 标签”。

### 6.2 词汇集合 Collection

| 字段       | 说明                                           |
| ---------- | ---------------------------------------------- |
| 集合名称   | 如“商务邮件词汇”“默认错题本”                   |
| 集合类型   | 普通单词书、自建集合、收藏本、错题本           |
| 来源       | 书籍、个人收集、测试自动生成、导入等           |
| 描述/封面  | 可选                                           |
| 默认错题本 | 同一时间仅一个集合为默认错题本                 |
| 排序方式   | 手动、加入时间、词汇顺序、学习状态、复习次数等 |
| 词汇成员   | 只保存词汇引用及集合内信息，不复制词汇正文     |

集合成员建议额外记录加入时间、来源页码/章节、集合内备注、手动排序序号。一个词汇可同时存在于多个集合中，同一集合内不可重复加入。

#### 集合、来源与标签的边界

- **来源集合**回答“这批词来自哪里”，例如 BJT、N1、BJT-外来语；必须继续保存来源文件、来源行和集合内顺序。
- **用户集合**回答“我准备如何使用这一组词”，例如《某书》第三章、今日新词、重点复习。
- **系统集合**承载收藏本、错题本等系统行为。
- **标签**回答“这个词有什么语言属性”，例如拟声词、拟态词、书面语、敬语；标签不保存集合顺序和学习进度。
- 一个集合可以通过标签筛选批量创建，但创建后拥有独立成员、顺序和统计。
- 删除或归档集合不会删除核心词汇；停用标签也不会自动删除集合成员。
- 现有收藏组优先原位升级或兼容映射为 `favorite` 类型集合，避免产生两套重复的收藏数据。

### 6.3 用户词汇进度 User Vocabulary Progress

用户提出的数值状态保留为对外简化规则：

- `0`：未学习。
- `1`：已学习、尚未复习。
- `>1`：已复习；每复习一次加 1。

为避免“状态值”和“复习次数”混淆，产品内部建议拆分为：

| 字段             | 规则                                                        |
| ---------------- | ----------------------------------------------------------- |
| 是否已学习       | 首次标记学习后为 true，此后不回退                           |
| 首次学习时间     | 只记录一次                                                  |
| 复习次数         | 初始 0，每完成一次复习加 1                                  |
| 最近复习时间     | 每次复习更新                                                |
| 下次建议复习时间 | 本系统 可按简单规则生成，可由用户调整                       |
| 收藏次数         | 非负整数；0 为未收藏，1 为普通收藏，大于 1 表示多次重点收藏 |
| 难度标记         | 未标记、简单、一般、困难；建议由用户主动设置                |

页面需要显示兼容状态值时，计算规则为：未学习 = 0；已学习且复习 0 次 = 1；已学习且复习 N 次 = N + 1。

> 重要说明：复习次数多不一定天然代表词汇更难，也可能只是学习时间更早。产品应同时提供“困难标记”和“测试错误次数”，不要只用复习次数判断难度。

### 6.4 学习与复习事件

每次操作都应保留事件记录，而不是只修改总次数：事件类型、词汇 ID、来源集合、发生时间、会话 ID、操作结果。这样才能支持学习历史、当日统计、撤销误操作和后续复习策略。

#### 本系统 初始进度规则

新建词汇的初始状态统一为未学习、复习次数 0、掌握次数 0、错误次数 0。学习、复习、掌握和测试事件均从用户在本系统中的实际操作开始记录。

### 6.5 测试记录

| 对象         | 关键内容                                                 |
| ------------ | -------------------------------------------------------- |
| 测试会话     | 来源集合、题量、题型、随机种子、开始/结束时间、完成状态  |
| 测试题       | 词汇、题型、选项、用户答案、正确答案、是否正确、答题耗时 |
| 词汇测试统计 | 总答题次数、总错误次数、连续正确次数、最近错误时间       |

词汇首次进入某个错题本时必须记录加入时间；再次答错已存在的词汇时不重复添加成员，但更新最近错误时间并累计实际错误次数。

错题本中的“错的次数”应来自测试题历史汇总，并可在错题本列表中展示。再次答对或标记“已掌握”都不自动移出错题本。

“保留历史并默认隐藏已掌握项”的具体含义是：

1. 用户在错题本中将词汇标记为“已掌握”后，错题本成员关系、首次加入时间、历次错误记录和掌握记录仍然保留，不删除数据。
2. 错题本默认筛选为“待掌握”，因此已掌握词汇不会继续占据日常复习列表。
3. 用户可切换到“全部”或“已掌握”筛选，随时查看历史，并可再次标记为待复习。
4. 每次执行“掌握”操作都新增一条掌握事件并更新“最近掌握时间”；若同一词汇掌握 N 次，则保留 N 条事件，汇总字段显示掌握次数 N 和最新操作时间。

这样既不会因自动移除丢失学习证据，也不会让已经掌握的词持续干扰日常错题复习。

### 6.6 语法 Grammar

字段包括：语法形式、读法（可选）、中文含义、接续方式、使用说明、备注、标签、创建/更新时间。语法可关联近义语法、相似语法、易混淆语法；关联关系需要有类型和说明。

### 6.7 句子 Sentence

字段包括：日语句子、中文翻译、假名/注音（可选）、来源、备注、创建/更新时间。句子可以关联多个词汇和多个语法，并允许标注词汇或语法在句中的片段位置。

### 6.8 关联关系

词汇与词汇之间的关联类型至少包括：同音词、近义词、反义词、相似词、易混淆词、派生词、相关词。关系应支持方向性，例如 A 是 B 的反义词可双向展示。词汇搭配不是词汇关系类型，统一保存到独立搭配表，再通过关联表连接一个或多个词汇。

示例：

```text
顧みる（かえりみる）
├─ 同音词：省みる
└─ 近义词：反省、振り向く、振り返る

基づく
├─ 关联语法：～に基づいて
└─ 关联句子：法律に基づいて罰する。
```

### 6.9 词汇、搭配、句子的存储方案

#### 结论

该方案已经产品确认。本系统 采用多个职责明确的数据表：词汇、词汇搭配、句子、语法分别存储，不在 `vocabulary` 表中增加通用 `type` 字段把四类内容混在一起。它们通过关联表组成知识网络，并通过统一的页面内搜索服务返回组合结果。

```text
vocabulary（词汇）
   ├─ vocabulary_collocation_links ─ collocations（词汇搭配）
   ├─ vocabulary_sentence_links ──── sentences（例句）
   ├─ vocabulary_grammar_links ───── grammars（语法）
   └─ vocabulary_relations ───────── vocabulary（关联词汇）

grammars（语法）
   ├─ grammar_sentence_links ─────── sentences（例句）
   └─ grammar_relations ──────────── grammars（关联语法）
```

#### 对象边界

| 对象     | 判断标准                                   | 示例                         | 核心字段                           |
| -------- | ------------------------------------------ | ---------------------------- | ---------------------------------- |
| 词汇     | 可以独立学习、解释和测试的词头             | `基づく`                     | 词汇、假名、翻译、词性             |
| 词汇搭配 | 围绕一个或多个词汇形成的常用组合或使用模式 | `事実に基づく`、`責任を負う` | 搭配正文、假名（可选）、翻译、备注 |
| 句子     | 具有完整表达和语境的例句                   | `法律に基づいて罰する。`     | 日语句子、翻译、注音（可选）、来源 |
| 语法     | 可复用的句型、接续或表达规则               | `～に基づいて`               | 语法形式、意思、接续、说明         |

固定短语如果本身作为独立词条学习，例如惯用语或固定表达，可以进入正式词汇库；仅用于说明某个词如何搭配的内容进入搭配表。审核页面需要允许用户把 AI 判断的对象类型改为词汇、搭配、句子或语法。

#### 单表加 `type` 的优点与问题

| 方面     | 单表 + `type`                                                                                    |
| -------- | ------------------------------------------------------------------------------------------------ |
| 优点     | 初期表数量少；可以用一个 ID 和一套简单 CRUD；做全文搜索较直接                                    |
| 字段问题 | 词汇需要词性，语法需要接续，句子需要来源，搭配需要关联词；大量字段只适用于部分类型，产生大量空值 |
| 约束问题 | 很难通过数据库约束保证“词汇必须有翻译”“句子不能选词性”“语法必须有意思”等类型规则                 |
| 关联问题 | 同一张表既关联自己又承担多种方向，关系类型复杂，删除、审核和查询更容易出错                       |
| 测试问题 | 词汇三向测试与语法意义测试规则不同，通用记录容易堆积大量条件分支                                 |
| 演进问题 | 任一对象增加专属字段都会扩大公共表，代码持续依赖 `type` 分支，长期维护成本高                     |

#### 多表方案的优点与代价

| 方面     | 多个专用表                                                               |
| -------- | ------------------------------------------------------------------------ |
| 优点     | 每类对象字段清晰、约束准确；CRUD、审核、测试、逻辑删除均可按对象独立演进 |
| 关联     | 通过明确的多对多关联表连接，能记录排序、关系类型、备注和创建时间         |
| 搜索     | 页面接口可并行查询相关表，或建立统一搜索索引/视图；无需牺牲核心数据规范  |
| 数据质量 | AI 导入后可按对象类型进入不同暂存区，审核通过后写入正确正式表            |
| 代价     | 表与 API 数量更多；跨对象搜索、导出和事务需要额外编排                    |

本项目属于长期积累型知识库，数据清晰和后续扩展比减少几张表更重要，因此选择多表方案。不要为了复用一个列表组件而把不同业务对象塞进同一数据表；前端组件复用和数据库结构统一是两件不同的事。

## 7. 功能需求

### 7.1 首页

- 展示词库总数、已学习数、已复习数、收藏数、错题数。
- 提供“继续上次学习”“开始今日复习”“快速测试”三个主要入口。
- 展示最近使用的词汇集合。
- 展示最近学习、最近复习和最近错题摘要；本系统 不计算复习提醒日期。
- 展示最近新增或编辑的词汇，便于继续补全资料。

### 7.2 核心词库

#### 列表与查询

- 使用分页，`pageSize` 固定可选 10、20、30、50、100。
- 支持模糊搜索日语词汇、假名、翻译、词汇搭配和句子正文。
- 搜索结果按命中类型分组或高亮，明确显示“词条命中”“搭配命中”“例句命中”。
- 词库页查询区只保留关键字输入框和独立“查询”按钮，不提供词性筛选控件；词性仍在词汇资料中维护，并可由后续高级筛选能力使用。
- 支持按词汇、假名、创建时间、复习次数、错误次数排序。
- 可批量加入集合、批量打标签、批量归档。

#### 页面 URL 与接口参数联动

- 搜索、筛选、分页和集合选择都属于当前页面或当前子路由自己的状态，不提供全局搜索框。
- 页面状态必须写入当前路由的 URL 查询参数，至少包括 `pageNum`、`pageSize`；其他页面按需使用 `collectionId`、`tagId`、`partOfSpeech`、`keyword`、`status` 等参数。
- 页面初始化、刷新、直接访问以及浏览器前进/后退时，必须从 URL 恢复表单和列表状态。
- 前端请求接口时，URL 中经过校验的 `pageNum`、`pageSize` 等查询参数应直接作为接口参数使用，不得由页面维护另一套相互冲突的分页状态。
- 用户修改筛选或搜索条件时，将 `pageNum` 重置为 1；只修改页码或每页数量时同步更新 URL 与接口请求。
- 接口返回总数、当前页、每页数量等分页元数据；若 URL 参数越界，接口或页面回退到合法值后应反向修正 URL。
- 前端使用普通 History 路由，不使用 Hash 路由。开发服务器和生产静态服务器必须把未知前端路径回退到 `index.html`，保证直接刷新 `/words`、`/grammars` 等路由不会返回 404。
- 词库、语法、句子、待掌握、已掌握、错题集、收藏本、导入审核、标签和词性等列表页面均需分页。
- 所有分页页面只在列表底部显示一套分页控件，整体水平居中，不允许把统计文字放左边、分页按钮放中间、跳页表单放右边形成三段式布局。
- 分页中心区域按顺序显示：上一页、连续页码、下一页、跳转页码输入框、跳转按钮、每页 X 条选择器。避免重复显示“第 X/Y 页”“共 X 条”等冗余信息；确需显示总数时只在列表标题或查询结果摘要中出现一次。
- 上一页、页码、下一页、跳转按钮必须使用同一 Bootstrap 尺寸、相同高度、边框和交互状态；禁用、当前页、悬停和键盘焦点样式保持一致。
- “每页 X 条”位于分页中心区域最右侧，是 `pageSize` 的唯一页面控件；修改后将 `pageNum` 重置为 1 并同步 URL 和接口参数。
- 所有分页页面使用 `pageNum`、`pageSize`；每页数量固定为 10、20、30、50、100。

#### 新增

- 必填：日语词汇、翻译。
- 可选：假名、词性、备注、标签、来源。
- 输入时提示疑似重复词汇，并展示已有词条摘要。
- 保存后可选择“继续新增”“查看详情”“扩展该词汇”。
- 桌面端表单统一使用 inline 布局：标签和输入控件位于同一行；手机端空间不足时允许上下两行。
- 词汇与输入框同一行，假名与输入框同一行，假名标签只显示“假名”。
- 翻译使用左对齐 `textarea`，标签与文本域在桌面端同一行。
- 词性和标签均非必选，默认空；二者都使用可输入过滤的多选下拉标签选择器，已选项以标签形式展示并可逐项移除，不允许自由创建枚举外词性。
- 新增/编辑 Modal 打开时使用覆盖完整视口的 Bootstrap Backdrop，页面所有背景区域均进入遮罩状态。

#### 编辑与删除

- 可编辑所有词汇基础信息。
- 删除前展示影响范围：所在集合、关联语法、关联句子、学习记录和测试记录。
- 词汇禁止物理删除。删除操作统一执行逻辑删除，记录 `deleted_at` 等删除信息。
- 逻辑删除词汇默认不出现在词库、集合、学习、复习、测试和页面内搜索中；管理页面可查看“已删除”并恢复。
- 恢复前重新执行重复检测；若正式库已出现同词条，提示用户选择恢复、合并或保持删除。
- 数据库外键不得依赖物理级联删除清空学习、集合、错题和关联历史。

#### 词汇详情/扩展二级页面

- 顶部展示词汇、假名、翻译、词性、收藏、学习状态及统计。
- 分区展示基础资料、关联词汇、搭配、关联语法、例句、所在集合、学习历史、测试统计。
- 添加关联词汇时必须从核心词库搜索选择；不存在时可先新增词汇，再自动建立关联。
- 可为关联关系添加说明，例如两个近义词的使用差异。
- 关联语法和句子同样从对应库搜索选择，也允许在当前页快速新增后关联。

### 7.3 词汇集合

- 创建、重命名、复制、归档和删除集合。
- 普通集合可手动添加/移除词汇，支持批量操作。
- 收藏按钮默认将词汇加入系统收藏本；后续可选择其他收藏本。
- 测试错题直接进入管理设置中唯一的默认词汇/语法错题本，测试过程不再改选错题本。
- 集合详情展示词汇数、学习进度、复习情况、测试正确率和最近使用时间。
- 一个集合可按章节或自定义分组；本系统 优先支持单层分组，不做无限层级目录。
- 支持集合内去重；跨集合不去重。
- 收藏本数量不设业务上限，可创建 N 个；同一用户必须且只能有一个默认收藏本。切换默认收藏本必须在同一事务中取消原默认并启用新默认，不允许出现多个默认。
- 错题本成员必须记录首次加入时间；后续错误只更新错误统计和最近错误时间，不覆盖首次加入时间。
- 集合卡片左上角的“来源集合”等类型标识必须是单行紧凑徽标，内容与高度匹配，不得出现两行高度却只显示一行文字。
- 集合卡片右上角省略号是 Bootstrap Dropdown 操作入口，至少提供编辑、复制和归档；每项操作必须真实修改本地/正式数据并给出通知，禁止保留无功能图标。

### 7.4 学习模式

#### 进入学习

“学习”一级页面本身是集合入口，以卡片平铺所有可用词汇或语法集合，不再设置独立“测试”一级页面。每张集合卡片展示名称、说明、类型、更新时间、对象数量和已掌握数量，并同时提供“学习”和“测试”按钮。学习进入 `/collections/:collectionId/learn`，测试进入 `/collections/:collectionId/test`；当前集合就是唯一范围。集合学习页顶部展示集合标题与说明，其下为显示选项和卡片列表，不提供范围、排序、进度或退出保存控件。

#### 列表字段

每个词汇展示：日语、假名、翻译、词性（次要）、收藏状态、学习状态。用户可点击“标记已学习”；已经学习的词汇不重复增加学习次数。

#### 显示模式

页面顶部只提供四个复选框：仅日语、仅假名、仅翻译、默记，不提供“全部”按钮。

- 默认仅日语、仅假名、仅翻译三个复选框全部勾选，即三个字段全部显示。
- 取消其中任意项，只隐藏对应字段；三个字段复选框允许任意组合和同时勾选。
- 勾选默记后，三个普通字段复选框保留原值但全部禁用；列表统一只显示日语，假名和翻译显示为“—”。
- 取消默记后，恢复三个普通字段复选框的可操作状态，并按进入默记前的勾选结果显示。
- 默记模式下仍可点击单个字段临时显示或隐藏，退出或重新进入默记时重置临时状态。

字段被隐藏时显示“—”并保留原区域高度，避免页面跳动。点击日语、假名或翻译所在区域，可单独在显示与隐藏之间切换；该操作只影响当前词条，不改变页面顶部的全局模式。应提供清晰的可点击提示，并支持键盘操作。

#### 响应式要求

- PC（建议宽度 ≥ 768px）：卡片网格，默认每行 2–3 张；卡片操作固定在底部。
- 手机（宽度 < 768px）：单列紧凑列表，主要操作可单手触达。
- 切换显示模式时不重置滚动位置、筛选条件或已标记进度。

### 7.5 复习模式

- 只能从已学习词汇中选择。
- 界面与学习模式一致，复用全部显示/隐藏能力。
- 完成一次复习后，保留已学习状态，复习次数加 1，并记录复习事件和时间。
- 支持逐词标记和“完成本页复习”；批量操作需要确认范围。
- 可按最近未复习、复习次数、困难标记、错误次数、建议复习时间筛选。
- 复习完成后展示本次词数、耗时和下次建议复习时间。
- 允许用户撤销刚刚的复习标记，避免误触造成次数错误。

### 7.6 测试模式

#### 测试配置

- 测试从学习首页的具体集合卡片进入，URL 必须包含集合 ID；刷新后按该 ID 从数据源恢复集合与题目。
- 测试页不再显示独立的 `TEST`、测试模式、对象类型和组数量标题区；相关说明归入集合卡片或集合测试页标题。
- 测试页面不提供“测试对象”下拉框，也不使用集合下拉框。
- 可测试的词汇集合和语法集合直接以卡片平铺；每张卡片显示集合名称、最后更新时间、对象数量、已掌握数量和待掌握数量。
- 每张集合卡片提供“测试这个集合”按钮；集合自身类型决定生成词汇题或语法题。
- 每组数量固定为 10、20、30、50、100；集合数量不足时使用全部，并提示实际数量。
- 题目顺序随机。
- 词汇题型：默认三种全部开启。
- 测试页面不选择错题本，直接使用“管理 > 设置”中的默认词汇错题本和默认语法错题本。

#### 三种必测题型

每个被抽中的词汇都需要完成以下三类题：

1. 日语 → 选择或输入假名。
2. 日语 → 选择或输入翻译。
3. 假名或翻译 → 选择日语词汇。

本系统 默认采用四选一，以延续现有项目体验。题型顺序随机，但同一词的三题应避免连续出现。后续可扩展输入题，不作为首期必需。

没有假名的词汇不生成“日语 → 假名”测试题，也不将缺少假名视为数据错误；该词仍参加词汇和翻译方向的测试。结果页的题量与正确率均按实际生成题目计算。

#### 干扰项规则

- 词汇题优先从同一集合中选择干扰项，再优先选择相同词性或相近读音的词汇。
- 翻译题必须解析正确词汇完整翻译中的所有含义，排除语义相同或可能同时正确的干扰项。
- 假名题不得出现相同读音的多个可选答案；无法生成三个有效干扰项时，应扩大候选范围或减少选项并明确提示，不得生成多解题。
- 所有干扰项必须排除当前正确答案和重复选项。

#### 语法测试

- 语法测试只测试“语法形式 ↔ 语法意思”，本系统 默认采用“显示语法形式，四选一选择意思”。
- 干扰项优先选择已建立关联的近义语法、相似语法和易混淆语法的意思；不足时从同一语法集合或相同标签中补足。
- 多个语法含义实质相同、可能同时正确时，不得同时作为同一道题的选项。
- 语法测试同样记录测试会话、题目、答案、正误、耗时、累计正确次数和错误次数。
- 语法错题进入语法错题本；词汇错题进入词汇错题本，两类对象不能写入错误的集合成员表。

#### 答题与结果

- 每次选择答案后立即自动保存题目、答案、正误和耗时，不提供手动保存按钮。
- 回答正确时显示短暂成功反馈，并自动进入下一题。
- 回答错误时显示错误提示和正确选项，自动写入对应默认错题本；留出可阅读时间后自动进入下一题。
- 错误时显示正确答案，并可查看词汇详情、收藏或标记困难。
- 中途退出时由于逐题自动保存，会话天然保留为未完成状态，允许继续或放弃。
- 结果页展示总正确率、按题型正确率、错误词汇、每词错误次数和耗时。
- 同一词在一次测试中任一题答错，即加入指定错题本；一次会话多题答错应按实际错误题数累计错误次数。

### 7.7 收藏本与错题本

- 两者复用词汇集合详情页面和学习显示/隐藏组件。
- 收藏本强调用户主动收集；错题本强调测试自动归集及错误统计。
- 列表均复用“仅日语、仅假名、仅翻译、默记”四个复选框与单字段点击显隐规则。
- 错题本额外显示总错误次数、最近错误时间、最近测试结果、是否已掌握。
- 收藏本额外显示收藏时间和收藏来源。

### 7.8 语法库

- 语法列表支持新增、编辑、逻辑删除、恢复、模糊查询、标签筛选，CRUD 整体交互与正式词库保持一致。
- 语法列表使用分页，URL 至少包含 `pageNum`、`pageSize`，搜索关键字同样写入当前 URL。
- 语法详情展示含义、接续、说明、相关语法、关联词汇和例句。
- 添加近义、相似、易混淆语法时，从语法库选择并填写关系类型与差异说明。
- 从词汇或句子详情进入语法详情后，提供清晰的返回路径。
- 新增或编辑语法时可以搜索并关联多个现有句子，也可以在语法表单中新增句子；从语法上下文新增的句子保存成功后自动建立语法—句子关联。
- 语法详情中的关联句子必须可点击进入句子详情；关联词汇、近义语法和相似语法同样可进入对应详情。

### 7.9 句子库

用户虽未明确要求独立句子页面，但为了维护和检索关联句子，本系统 建议补充句子列表：

- 支持新增、编辑、逻辑删除、恢复、模糊查询，CRUD 整体交互与正式词库保持一致。
- 句子列表使用分页，URL 至少包含 `pageNum`、`pageSize`，搜索关键字同样写入当前 URL。
- 可从句子关联多个词汇和语法。
- 句子详情展示日文、翻译、注音、来源、备注及全部关联对象。
- 可从词汇扩展页或语法详情页快速创建句子并自动带入关联。
- 句子详情中的关联词汇和关联语法均可点击进入对应详情；从句子编辑页添加或移除关联后，词汇和语法详情同步体现关系。

### 7.13 详情页关联跳转

- 词汇详情中的关联词汇点击进入目标词汇详情。
- 词汇详情中的搭配、句子和语法点击进入相应对象详情。
- 语法详情中的关联语法、关联词汇、关联句子点击进入相应详情。
- 句子详情中的关联词汇和关联语法点击进入相应详情。
- 关系是双向可见的：在语法下关联句子后，句子详情必须显示该语法；在句子下关联词汇后，词汇详情必须显示该句子。
- 删除关联只删除关系记录，不删除任何正式词汇、语法、句子或搭配对象。

### 7.10 页面内搜索

产品不提供顶部全局搜索。词库、集合、语法、句子、标签和管理页各自在页面内容区提供与本页对象相符的搜索表单。

- 词库页搜索范围包括词汇正文、假名、翻译、备注、搭配和关联句子正文。
- 语法页搜索语法形式、含义、接续、备注和关联例句。
- 句子页搜索日语句子、翻译、来源和关联对象。
- 集合页搜索集合名称、说明和来源；集合详情页只搜索当前集合成员。
- 搜索结果应高亮命中片段；词库因搭配或句子命中时，需要显示命中来源。
- 支持包含匹配；日语假名输入应支持平假名/片假名归一化。
- 搜索关键字和筛选条件写入当前页面 URL，并直接参与接口请求。
- 所有查询表单统一为左侧关键字输入框、右侧独立 Bootstrap 查询按钮；按钮同时显示 Bootstrap Search 图标和“查询”文字，不使用仅图标按钮或把图标嵌入输入框。

### 7.11 知识页面导航

- 本系统 知识模块只包含语法与句子，文章模块和文章入口移除。
- 知识页面内容区顶部必须提供一级/二级页面内导航，可在“语法”和“句子”之间跳转；不得要求用户只能通过全局顶部导航切换。
- 语法、句子及其详情使用独立 History 路由，关联对象可互相进入详情。

### 7.12 标签管理

- 标签管理是“管理”一级导航下的独立二级页面，具有独立 URL。
- 支持标签新增、查询、编辑、排序、启用和停用；已有词汇引用的标签不得物理删除。
- 标签名称必须唯一，并使用统一规范，避免简繁体、日中写法或空格差异造成重复。
- 标签列表显示引用词汇数；停用标签后历史关联继续显示，但新增/编辑词汇时默认不再提供选择。
- 本系统 初始化时可预置拟声词、拟态词、书面语、口语、敬语、易混淆等常用标签，但这些只是可管理的初始数据，不应写死在页面代码中。

## 9. 建议补充的功能

以下能力是根据现有项目和上述需求补充，仍保持“不做考试功能”的边界。

### 9.1 管理端导入审核与 CSV 导出（高优先级）

导入、审核和导出统一放在“管理”一级导航下，使用独立二级页面和独立 URL。

#### CSV 导出

- 正式词汇库支持导出 CSV，不要求面向用户提供 JSON 导出。
- 导出范围支持当前页面查询结果、当前集合、手动勾选和全部正式词汇。
- CSV 至少包含词汇、假名、翻译、词性、标签、逻辑删除状态和创建/更新时间；关联搭配、例句、语法如需导出，使用独立 CSV，避免一行中嵌入复杂结构。
- 导出操作显示 Loading，完成后记录导出时间、导出范围和记录数量。

#### 非正式词汇表（导入审核池）

所有外部导入内容不得直接写入正式词汇库。第一次写入统一进入“非正式词汇表”，也称“导入审核池”。每次导入形成一个批次，保留原始文件、原始文本、AI 解析结果、批次时间和处理状态。

审核池单条数据至少包含：

| 字段         | 说明                                               |
| ------------ | -------------------------------------------------- |
| 导入批次     | 本次 AI 解析或文件导入任务                         |
| 原始内容     | 用户交给 AI 的原始行、段落或文件片段               |
| 建议对象类型 | 词汇、搭配、句子或语法，可由审核者修改             |
| 词汇/正文    | AI 解析出的日语内容                                |
| 假名         | 可为空                                             |
| 翻译/意思    | 按 本系统 翻译分隔规则规范化                       |
| 建议词性     | 必须映射到固定词性                                 |
| 建议标签     | 只引用现有标签 ID                                  |
| 建议集合     | 只引用现有集合 ID                                  |
| 重复检测结果 | 不重复、正式库已存在、疑似重复、批次内重复         |
| 审核状态     | 待审核、已批准、已拒绝、无需导入、需修改、导入失败 |
| 审核信息     | 审核时间、备注、正式库目标 ID                      |

#### AI 指令与 CSV 导入流程

“导入审核”页面不直接接收原始材料，也不在站内调用 AI。页面提供一段可复制的标准 AI 指令，要求外部 AI 按给定 MySQL/本系统 字段结构解析用户材料，并只输出 UTF-8 CSV。用户取得 CSV 后，在该页面上传；系统校验并写入非正式词汇表，然后开始人工审核。

```text
原始文件/文本
  → 用户使用页面提供的指令交给外部 AI
  → AI 输出约定结构的 UTF-8 CSV
  → 用户在“导入审核”页面上传 CSV
  → CSV 校验、固定枚举映射并写入非正式词汇表
  → 页面预览、修改、逐条或批量审核
  → 重复检测
  → 批准后事务写入对应正式表及集合/标签关联
```

- 页面必须清楚展示 AI 指令、CSV 必需列、对象类型枚举、词性枚举、翻译分隔规则和“未知字段留空、禁止编造”的要求。
- 用户可逐条批准，也可勾选多条批量批准、拒绝或标记无需导入。
- 批量批准前必须展示将新增、已存在、疑似重复、无效数据的数量。
- 正式词汇库存在相同词汇时，页面显示“已存在”和目标词汇链接；默认将该候选标记为“无需导入”，不得重复创建。
- “已存在”的精确判断至少比较规范化词汇；若词汇相同但假名或翻译不同，标记为“疑似重复”，交给用户选择保留正式数据、用候选更新、合并字段或仍创建新词。
- 批准操作必须使用事务；正式写入成功后才把审核状态改为“已批准”并记录目标 ID。
- 审核池数据采用逻辑删除并保留批次审计记录。

### 9.2 重复词检测与合并（高优先级）

- 新增和导入时识别疑似重复。
- 合并词汇时迁移集合成员、收藏、错题、关联关系和学习记录。
- 合并前逐字段展示正式数据与候选/重复数据的差异，由用户选择保留左侧、保留右侧、按翻译规则合并或取消操作。
- 用户必须明确确认是否保留每个冲突字段；系统不得在有冲突时静默覆盖。
- 合并后被合并词汇执行逻辑删除，并记录其合并目标 ID，确保旧引用可追溯。

### 9.3 学习会话保存（高优先级）

- 学习、复习和测试中途退出均保存进度。
- 首页提供继续入口。
- 会话过期后仍保留已完成的逐词记录。
- 会话保存当前对象、来源集合、题目顺序、当前题号、已完成答案和最后操作时间。
- 本系统 暂不提供按 1、3、7、14、30 天计算的复习提醒或建议日期。

### 9.4 操作历史与可撤销（中优先级）

- 对学习、复习、收藏、加入集合、归档等高频操作提供短时撤销。
- 对批量编辑和合并保留操作记录，降低误操作风险。
- 逻辑删除、批量审核、重复合并和正式导入必须记录操作前后摘要、时间和结果。

### 9.5 数据完整性提示（中优先级）

- 在词库提供“待补全”筛选：缺假名、缺词性、缺例句、缺关联等。
- 词条详情显示资料完整度，但不强制用户一次填完。
- 审核池提供“缺词汇、缺翻译、未知词性、标签不存在、关联对象不存在”等校验筛选。
- 不提供全局“＋”快捷连续导入。非系统格式的批量材料统一经过 AI 解析和非正式词汇审核流程。
- 正式库仍保留单条 CRUD 新增，适用于用户已经明确知道结构的少量数据。

### 9.6 无障碍与键盘效率（基础要求）

- 显隐状态不能只用颜色表达。
- PC 支持键盘切换答案、显示字段、收藏和标记学习。
- 所有点击区域满足移动端触控尺寸，焦点状态清晰。

## 10. 关键业务规则

1. 词汇必须先存在于核心词库，才能加入任何集合或建立词汇关联。
2. 单词书、收藏本、错题本不会复制词汇正文；编辑词库词条后，所有集合同步显示新内容。
3. 学习只首次生效一次；重复点击不得增加次数或重置首次学习时间。
4. 未学习词汇不能直接产生正式复习记录；若用户在复习入口操作，应先提示标记为已学习。
5. 每完成一次复习，复习次数加 1，并新增一条复习事件。
6. 删除集合不会删除核心词汇和学习记录；删除词汇只做逻辑删除，并保留全部引用和操作历史。
7. 测试抽样单位是“词汇”，每个入选词汇必须完成三类题。
8. 测试错误按错误题数累计；加入错题本按词汇去重。
9. 同一词汇可以在多个错题本中，但一次测试默认只写入一个指定错题本。
10. 逻辑删除词汇默认不出现在学习、复习、测试和搜索结果中，只能在管理筛选中查看和恢复。
11. 页面顶部显示模式是会话级偏好；单个词条的临时显隐不影响其他词条。
12. 用户离开页面后，可记住最近一次全局显示偏好；再次进入默记时，单词的临时展开状态应重置。
13. 一个用户可拥有 N 个收藏本，但任何时刻只能有一个默认收藏本；普通收藏操作直接写入默认收藏本。
14. 每次掌握操作都记录独立事件并更新最近掌握时间；标记掌握不删除错题本成员。
15. 本系统 暂不提供基于日期的复习提醒；用户从已学习词汇、错题和掌握记录中主动发起复习。

## 11. 非功能需求

### 11.1 性能

- 常规列表与搜索操作应在用户可感知的短时间内反馈。
- 大集合需分页或虚拟加载，避免一次渲染全部词汇。
- 搜索输入采用合理防抖，但回车可立即查询。

### 11.2 数据安全

- 破坏性操作二次确认；词汇、导入审核记录和有关联历史的业务对象使用逻辑删除。
- 导入、合并、批量删除前提供预览。
- 用户可在管理页面按对象导出 CSV；复杂关联对象分别导出，保证结构清晰。

### 11.3 一致性

- 学习、复习、收藏本、错题本共用同一套词汇展示与显隐规则。
- 词汇、语法、句子的关联入口与选择器交互保持一致。
- PC 与手机功能等价，布局可以不同。

### 11.4 UI 技术与主题规范

- UI 组件统一使用 Bootstrap 最新稳定版。PRD 编写时官方稳定版为 Bootstrap `5.3.8`；开发启动时再次核对官方稳定版，升级后必须完成兼容性验证。
- CSS 源码统一使用 SCSS；通过 Bootstrap Sass 变量、Maps、Mixins 和 CSS Variables 定制，不复制或另造 Bootstrap 已有组件交互。
- 默认视觉主题采用浅蓝色。建立唯一的全局主题入口，集中定义 `$primary`、页面背景、正文、边框、链接、成功、警告、危险等语义颜色，并编译/映射为 `--bs-*` 或项目级 CSS Variables。
- 页面和组件不得散落硬编码主题色值；需要切换主题时，只修改主题配置或切换根节点主题属性，不逐页改样式。
- Navbar、Nav、Dropdown、Card、Form、Table、Pagination、Modal、Offcanvas、Toast、Tooltip、Spinner、Placeholder、Button、Badge 等优先直接采用 Bootstrap 标准组件与交互。
- 存在二级页面的导航统一使用 Bootstrap Dropdown；手机导航使用 Bootstrap Navbar Collapse 或 Offcanvas。
- 图标只允许使用官方 Bootstrap Icons。Bootstrap Icons 是与 Bootstrap 配套但独立发布的官方图标库；PRD 编写时版本为 `1.13.1`。若官方库没有所需图标，则改用文字按钮，不引入其他图标库，也不自行绘制图标。
- 纯图标按钮必须具有 `aria-label`，必要时配合 Bootstrap Tooltip；装饰图标应对辅助技术隐藏。
- 页面切换和局部内容切换使用轻量淡入淡出；遵守系统 `prefers-reduced-motion`，减少动画模式下取消非必要过渡。
- 所有 CRUD 请求在提交按钮和受影响区域显示 Loading。提交期间按钮禁用并加同步锁，防止重复 POST；列表加载优先使用 Bootstrap Spinner、Placeholder 或明确的加载状态。
- 成功、错误和撤销提示优先使用 Bootstrap Toast 或 Alert，并保持现有通知语义一致。

### 11.5 收藏通知

- 收藏和取消收藏成功后显示轻量通知，内容至少包含操作结果和词汇名称；收藏成功时可同时显示实际收藏本名称。
- PC 端通知栈固定在页面右上角、主导航下方，不阻挡导航与主要操作。
- 手机端通知栈固定在屏幕顶部居中，并与屏幕左右保留安全间距。
- 单条通知显示 2 秒后自动消失。
- 短时间内触发多个通知时按触发顺序上下堆叠；每条通知使用自己的 2 秒计时，消失后其余通知自动补位。
- 通知区域使用 `aria-live="polite"`，不抢夺键盘焦点，不阻挡页面点击。
- 收藏与取消收藏通知使用浅绿色成功样式；失败时使用 Bootstrap 危险语义颜色并保留足够时间供用户读取。
- 收藏、取消收藏、掌握等一次操作只产生一条通知。通知调用不得放在 React 状态更新器等可能被重复执行的函数中；开发模式 StrictMode 下也必须保证不会重复提示。

### 11.6 表单布局

- 所有表单在桌面端使用 inline 结构，字段标签和控件位于同一行并保持统一标签宽度。
- 手机端允许标签和控件上下两行，控件占满可用宽度。
- inline 指的是单个字段的标签与控件同行，不要求把整个复杂表单强行挤在一行。

### 11.7 Demo 本地数据与交互完整性

- 本系统 Demo 使用浏览器 `localStorage` 作为模拟数据库，第一次打开时写入版本化初始化数据。
- 本地数据至少包含词汇、词性、标签、集合、词汇集合成员、语法、句子、词汇关系、词汇—语法、词汇—句子、语法—句子、收藏、错题、掌握记录、导入审核项和系统设置。
- Demo 中的新增、编辑、逻辑删除、恢复、收藏、取消收藏、掌握、审核、关联和设置修改必须写回 `localStorage`，页面切换或刷新后继续保留。
- 初始化数据带 schema/version 标识；版本不匹配时由 Demo 明确重置或迁移，禁止不同版本数据静默混用。
- 管理设置提供“重置 Demo 数据”操作，用于清除本地修改并恢复初始化数据。
- `localStorage` 只用于纯前端 Demo，不代表正式系统数据库方案；正式开发仍使用 PRD 定义的多表数据库模型。

### 11.8 导航与路由可用性

- 首页、学习、集合、复习及所有下拉导航必须可以点击并展示对应页面；集合卡片中的学习、测试入口必须进入带集合 ID 的正确内容，不能出现 URL 改变但内容未切换或链接无响应。
- 普通导航、下拉导航、卡片入口和详情关联跳转必须复用同一 History 路由方法，禁止混用 Hash 链接。
- 浏览器前进、后退、直接输入二级 URL 和刷新二级 URL 都必须恢复正确页面与 URL 查询状态。

### 11.9 PRD 完整性约束

本文件是 本系统 后续开发的完整业务依据。用户在历次评审中确认的功能、业务规则、交互、响应式、路由、分页、数据结构、枚举、导入审核、通知、测试和关联要求必须整理到本文件，不得只存在于聊天记录或 Demo 代码中。后续开发以本 PRD 为准；若 Demo 与 PRD 冲突，以最新确认并写入本 PRD 的规则为准。任何需求变更应先更新本文件，再修改正式代码。

### 11.10 收藏次数与重点收藏

- 词汇收藏使用 `favorite_count` 非负整数，不再使用布尔字段：0 表示未收藏，1 表示普通收藏，大于 1 表示执行过重点收藏。
- `favorite_count = 0` 时普通收藏图标为灰色；点击后写为 1，图标变为深色，并加入默认收藏本。
- `favorite_count >= 1` 时显示独立的重点收藏图标；每点击一次只将计数加 1，普通收藏图标继续保持深色，并显示当前次数。
- 点击已激活的普通收藏图标执行取消收藏，将计数重置为 0，并隐藏重点收藏图标。普通收藏与重点收藏每次操作都写入事件时间并只产生一条通知。
- 收藏次数与学习状态、复习次数完全独立，不再复用 0/1/>1 的学习状态含义。

### 11.11 复习与知识页内导航

- 复习页面内容区顶部使用 Bootstrap 导航条切换且只包含“已掌握”“错题集”“收藏本”，不使用胶囊式 Tab，也不出现“待掌握”等其他主入口。
- 三个入口均有独立 History URL；下方列表按当前入口切换，至少显示词汇、假名、翻译、错误次数和最近操作时间。
- 知识页面内容区顶部同样提供“语法”“句子”的页内导航，支持一级入口与详情二级页面之间返回和跳转。

### 11.12 响应式列表

- 所有桌面端表格在手机宽度下不渲染为可横向滚动表格，改为单列流式卡片；卡片保留该行的核心字段与操作。
- 桌面表格和手机卡片读取同一份查询、分页与 localStorage 数据，操作后两种视图必须同步。
- 词汇学习卡片仅在存在数据时显示搭配、句子、语法分区；空关联不显示标题、占位横线或空白区域。

### 11.13 Demo 完整业务模拟

- 初始化集合必须实际关联足量词汇或语法，学习与测试按 URL 集合 ID 从 `localStorage` 读取对象，不得只放一条硬编码测试题。
- 词汇集合测试按集合成员生成多道题和干扰项；答对自动保存并进入下一题，答错保存、显示正确答案和提示后再自动进入下一题。
- 集合的编辑、复制、归档，词汇/语法/句子 CRUD、关系维护、收藏次数、错题、掌握、查询和分页交互均须持久化；刷新与浏览器前进后结果不丢失。
- 首页四张统计卡均是可点击入口；词库卡片单位文案为“正式词汇”，已学习和错题卡分别进入对应页面。

### 11.14 页面标题与分层导航统一规范

- 顶部一级导航固定顺序为：首页、集合、词库、语法、句子、复习、管理；不再设置“学习”一级导航，也不使用“知识”下拉菜单包裹语法和句子。
- 所有页面标题区移除英文 Eyebrow。主标题使用较当前版本更小字号和紧凑上下间距；说明文字作为主标题下方副标题。
- 集合学习与集合测试都是“集合”的二级页面。页面标题区顶部显示面包屑式二级导航“词汇集合 / 当前集合名称”；“词汇集合”可返回集合页面，当前名称表示当前位置。
- 集合学习与测试页直接以集合名称作为主标题、集合说明作为副标题，不重复显示“集合学习”“集合测试”“当前集合就是学习范围”等通用标题，也不把标题信息包在卡片中，不显示集合类型徽标。
- 集合学习卡片不显示学习/未学习状态图标；收藏和重点收藏仍保留。
- 复习页面使用同一套二级导航呈现“已掌握、错题集、收藏本”，每个入口具有独立 URL，当前位置使用一致的激活状态。
- 管理页面使用同一套二级导航呈现“导入审核、标签、词性、设置”，每个模块顶部均显示该导航，不得只依赖全局下拉菜单。
- 词汇、语法、句子详情页使用同一套层级导航：一级列表入口可返回对应列表，二级显示当前对象名称；详情内部的资料、关系或记录属于三级导航，并使用统一样式与可交互状态。

### 11.15 列表字段与可用操作

- 正式词库列表列名使用“词汇搭配”，不使用含义不清的“匹配内容”。只有在搜索命中搭配或句子时，才在专门的搜索摘要中说明命中来源。
- 词库每行操作必须可用：编辑打开已填充表单并保存到数据源；逻辑删除需要确认并持久化删除状态；查看详情通过词汇名称进入。
- 语法列表不显示右侧箭头图标；语法形式本身作为详情链接。
- 语法卡片的关联句子显示可读的句子正文并可进入句子详情，不显示句子 ID，也不只显示关联数量。

### 11.16 二级导航最终位置与交互

- 所有二级导航或层级导航统一位于页面内容最顶部，顺序固定为：二级导航/面包屑、主标题、副标题、三级导航或业务内容。
- 集合学习和测试显示“词汇集合 > 当前集合”；复习显示“复习 > 已掌握/错题集/收藏本”；管理显示“管理 > 导入审核/标签/词性/设置”。父级文字可返回父级默认入口，当前子页面不可重复跳转。
- 顶部一级导航“复习”和“管理”不使用 Dropdown；点击后分别直接进入“已掌握”和“导入审核”。
- 词汇、语法、句子详情页的层级导航同样放在主标题上方，详情内部三级导航必须可点击切换真实内容，不允许只显示不可交互文字。
- 导航 Hover、键盘焦点和当前选中状态使用明显的主色背景/文字或下划线对比，满足可辨识性要求。

### 11.17 详情页与集合维护补充

- 集合学习卡片的词汇文字可点击进入词汇详情。
- 词汇详情三级模块包括关联资料、学习与测试记录；历史内容可查看，编辑和逻辑删除必须可执行并持久化。没有搭配、关联词汇、句子或语法时，对应模块完全不渲染。
- 语法详情移除“测试这个语法”按钮；提供可用的语法编辑、逻辑删除、关联资料及学习与测试记录。
- 词汇、语法、句子详情页共享一致的层级导航、三级导航、编辑和逻辑删除交互。
- 集合列表提供“创建集合”按钮并写入数据源。单个集合菜单只提供编辑和逻辑删除，不提供复制、归档。
- 集合卡片、语法卡片采用更紧凑的内边距和内容间距；语法形式与含义必须达到清晰文字对比度。

### 11.18 二级菜单与详情标题最终修正

- 复习页面必须保留横向二级菜单“已掌握、错题集、收藏本”。选中菜单后，在菜单下方显示“复习 > 当前模块”，再显示当前模块标题、副标题和内容；三个功能页面均保留。
- 管理页面必须保留横向二级菜单“导入审核、标签、词性、设置”。选中菜单后，在菜单下方显示“管理 > 当前模块”，再显示标题、副标题和内容；四个功能页面均保留。
- 词汇、语法、句子详情页不显示额外的通用页面主标题与副标题。页面从“列表名称 > 当前对象”层级导航直接进入对象详情解析。
- 复习列表不提供“掌握”按钮；已掌握状态的产生与维护由其他学习流程负责。

## 14. 验收标准

### 14.1 词库与集合

- 新增一个词汇后，可把它加入多个集合；编辑词汇后，所有集合同步更新。
- 对词汇、假名、翻译进行模糊搜索均能命中正确词条。
- 搜索句子片段能返回句子及其关联词汇。
- 同一集合重复加入同一词汇时，系统提示已存在且不产生重复成员。
- 词库 `pageSize` 只提供 10、20、30、50、100，切换后 URL、页面状态和接口参数一致。
- 可创建多个收藏本，但始终只有一个默认收藏本。

### 14.2 学习与复习

- 未学习词汇首次标记后状态从 0 变为 1。
- 再次标记学习不会改变首次学习时间，也不会增加学习次数。
- 完成第一次复习后兼容状态值变为 2，第二次变为 3，同时保留已学习状态。
- 每次复习均可在历史中看到独立记录。
- PC 显示卡片网格，手机显示单列列表。

### 14.3 显示与默记

- 默认“仅日语、仅假名、仅翻译”三个复选框全部勾选，因此三个字段全部显示。
- 三个普通字段复选框允许任意组合；取消勾选后只隐藏对应字段。
- 勾选默记后，三个普通字段复选框禁用，列表只显示日语；取消默记后恢复原勾选状态。
- 默记模式下点击单个隐藏字段可显示，再次点击可隐藏，不影响其他词汇。
- 显示模式切换不丢失当前学习进度与滚动位置。

### 14.4 测试与错题

- 选择 10 个且全部具有假名的词后生成 30 道题，每个词覆盖三类题，顺序随机且同词题目不连续出现。
- 没有假名的词不生成假名题，实际题量和正确率按已生成题目计算。
- 答错一题后，该词进入指定错题本；若已存在则不重复加入。
- 同一词答错多题时，错误次数按实际错题数增加。
- 结果页可按词汇与题型查看错误情况。
- 测试组数量只提供 10、20、30、50、100。
- 语法可单独测试，也可与词汇混合测试；语法干扰项优先使用近义、相似和易混淆语法。
- 词汇加入错题本时保存首次加入时间；标记掌握后默认从待掌握列表隐藏，但可在全部/已掌握中查看完整历史。

### 14.5 关联数据

- 可将“顧みる”关联到核心词库中的“省みる”等词汇，并标记关系类型。
- 可将“基づく”、语法“～に基づいて”和句子“法律に基づいて罰する。”互相关联。
- 从三个对象任意一方进入详情，都能看到另外两方的关联并可跳转。

### 14.6 导入审核与数据重建

- 新词汇初始学习、复习、掌握和测试统计均为 0，不读取任何历史表。
- 原始材料经 AI 解析后只能进入非正式词汇表，不能直接进入正式库。
- 审核者可逐条或批量批准、拒绝、修改和标记无需导入。
- 正式库已存在相同词汇时，候选显示目标词汇并默认标记“无需导入”；疑似重复由用户决定保留或合并。
- 批准成功后记录正式对象 ID、批准时间和导入批次，重复提交不得创建第二条正式数据。
- 管理页面可按当前查询、集合、勾选范围或全部导出 CSV。
- 删除正式词汇后数据库记录仍然存在，默认业务查询不可见；在管理页面恢复后重新可见。
- 词汇、搭配、句子、语法存储在各自专用表中，并可通过关联表互相跳转。

### 14.7 分页、路由与 Demo 持久化

- 每个列表查询页面底部只显示一套居中的统一分页控件，不出现左右分散或重复统计。
- 分页包含上一页、页码、下一页、跳转输入与按钮、每页 X 条；所有按钮尺寸与样式一致。
- 修改页码、跳页和每页数量后 URL 的 `pageNum`、`pageSize` 与页面结果同步。
- 首页、学习、集合、复习、下拉导航、集合学习/测试按钮和所有详情关联链接均可进入正确页面。
- 直接刷新任意 History 二级路由不会返回 404，也不会回到错误页面。
- Demo 新增词汇、语法或句子后，刷新页面数据仍存在；关联关系、收藏和设置同样保留。
- 重置 Demo 数据后恢复初始化数据，并清除用户在本地创建的模拟记录。

### 14.8 语法、句子与关联

- 语法和句子列表均具有与词库一致的新增、编辑、逻辑删除、搜索、分页和 Loading 交互。
- 从语法表单新增或选择句子后，语法详情显示关联句子，句子详情同步显示关联语法。
- 词汇详情中的关联词汇、句子和语法均可点击进入正确详情。
- 句子详情中的关联词汇和语法、语法详情中的关联词汇和句子均可点击进入正确详情。

## 15. 暂不纳入 本系统

- JLPT、BJT 等考试题库、模拟考试和等级预测。
- 社区、好友、排行榜、公开分享与评论。
- 教师布置任务、班级和多人协作。
- 商业化、订阅、积分商城和复杂成就系统。
- 自动生成词义或自动判定语言内容正确性。
- 完整的间隔重复算法；本系统 只保留可扩展的数据与简单建议。

## 16. 已确认的产品决策

1. 翻译只使用一个字段；不同含义用 `。` 分隔，相近译法用 `、` 分隔。
2. 没有假名的词汇忽略假名测试，不阻塞其他题型。
3. 词汇干扰项优先来自同一集合、相同词性或相近读音，并严格避免多解。
4. 错题标记掌握后不移除：保留成员和全部历史，默认只在“待掌握”视图中隐藏，可通过“全部/已掌握”查看。
5. 收藏本支持 N 个，但同一时间只能有一个默认收藏本。
6. 本系统 暂不提供复习建议日期和日期提醒。
7. 测试支持词汇、语法、词汇 + 语法；语法测试含义，干扰项优先使用近义和相似语法。
8. 测试组数量和词库每页数量统一为 10、20、30、50、100。
9. 页面查询状态由当前路由 URL 驱动，并直接转换为接口参数。
10. UI 使用 Bootstrap 最新稳定版、Bootstrap Icons 和 SCSS；默认浅蓝主题，主题变量集中配置。
11. 不提供全局搜索，各业务页面维护自己的搜索、筛选、分页和 URL 参数。
12. 管理端使用 AI 将非标准材料解析到非正式词汇表，人工批准后才能进入正式库。
13. 正式词汇只做逻辑删除，不执行物理删除。
14. 本系统不读取或迁移任何历史业务表；所有数据通过正式录入或导入审核进入。
15. 词汇、搭配、句子、语法使用多个专用表，不使用单表 `type` 混存方案。

---

本 PRD 的核心结论是：本系统 不应继续把背诵本、错题本、单词书分别实现为孤立的数据模块，而应以核心词库为唯一事实来源，以词汇集合承载不同使用场景，以学习事件、复习事件和测试事件记录行为，再用词汇—语法—句子关联构成完整的个人日语知识库。
