# 日本語言葉勉強：项目需求文档

> 本文档是当前产品业务需求的唯一正式版本。技术实现参见《前后端技术架构》，数据表定义参见《数据库结构》。

## 1. 产品定义

### 1.1 产品定位

“日本語言葉勉強”是面向日语学习者的在线词汇学习工具，以 BJT、N1、BJT-外来语等词库为数据源，提供学习、测试、复习、收藏、词库维护、知识文章和项目管理功能。

### 1.2 产品目标

1. 建立可持续维护的日语词汇库。
2. 形成“学习 → 测试 → 错题/掌握 → 复习”的闭环。
3. 使用多标签组织词汇与文章，业务关系统一使用 ID。
4. 支持电脑端和手机端高效操作。
5. 在代码仓库中集中维护产品需求，避免站内文档与代码版本不一致。

### 1.3 设计原则

| 原则 | 要求 |
|---|---|
| 简洁 | 完成常规背词功能，不引入不必要的复杂流程 |
| 高效 | 卡片紧凑、操作反馈及时、减少重复选择 |
| 随机 | 学习顺序、题型、题目和选项避免固定顺序 |
| 持久化 | 词汇、进度、收藏、文章和配置使用在线数据库 |
| 响应式 | 所有核心页面适配电脑和手机 |

## 3. 数据与类别规则

### 3.1 词汇来源

- BJT：[BJT 汇总](https://github.com/weizhiqimail/japanese-vocabulary-site/blob/main/files/vocabulary/BJTSummary.md)及[BJT 补充词汇](https://github.com/weizhiqimail/japanese-vocabulary-site/blob/main/files/vocabulary/BJT-%E8%AF%8D%E6%B1%87.txt)。
- N1：[N1 词汇 CSV](https://github.com/weizhiqimail/japanese-vocabulary-site/blob/main/files/vocabulary/N1-%E8%AF%8D%E6%B1%87.csv)，由原始 XLSX 直接转换。
- BJT-外来语：[BJT 外来语](https://github.com/weizhiqimail/japanese-vocabulary-site/blob/main/files/vocabulary/BJT-%E5%A4%96%E6%9D%A5%E8%AF%AD.txt)。
- 文章：[文章来源文件](https://github.com/weizhiqimail/japanese-vocabulary-site/blob/main/files/vocabulary/%E6%96%87%E7%AB%A0.txt)。

这些文件是可追溯的原始来源；网站运行时使用已导入在线 MySQL 的数据。

### 3.1.1 导入完整性

- 来源中的单词、固定搭配、短语和完整句子都属于词汇学习条目，不得因为不是单个词而忽略。
- BJT、BJT 补充和 BJT-外来语先处理，N1 后处理。
- 每次导入必须先生成来源与数据库差异，再在事务中写入缺失项和标签。
- 写入后必须按来源逐条反向核验；“缺失”和“缺标签”都为 0 才算完成。
- 并列词条应拆成独立条目；完整句子不得随意拆成残句。
- 明显错误的日语字形、假名和词条边界应在导入前纠正；正确内容保持原样。
- 固定搭配和完整句子没有可靠完整读音时，假名允许为空，且不生成假名测试题。
- 数据按来源顺序保存；类别内浏览顺序不得被跨类别去重或补录时间打乱。
- 外来语中的括号可能是可省略后缀，不得一律解释为假名。
- N1 的翻译和补充说明列必须全部保留。
- 只有预填格式、没有词面、读音或释义的空白模板行不作为词汇。

### 3.2 类别与标签

- 类别也作为标签使用。
- 一个词汇可以属于多个类别。
- 一篇文章可以属于多个类别。
- 所有关联使用类别 ID，不依赖类别名称常量。
- 类别具有名称、适用对象、用途、排序和启用状态。
- 类别允许新增、修改、查询、启用和停用，不允许删除。

## 4. 首页

- 页面标题为“日本語言葉勉強”。
- 展示词库数量、待背数量、已掌握数量和需复习数量。
- 提供进入今日学习的入口。
- 全站使用无衬线字体。
- 统计数据来自在线数据库。

## 5. 学习

### 5.1 学习参数

| 参数 | 规则 |
|---|---|
| 词汇分类 | 位于学习页面内容区，不作为全局筛选 |
| 每组数量 | 固定为 10、20、30、40、50、100，默认 30 |
| 显示字段 | 日语、假名、翻译可独立显示或隐藏 |
| 抽取规则 | 从当前类别未学习词汇中随机抽取 |

### 5.2 卡片

- 页面标题为“学习单词”。
- 电脑端每行三张紧凑卡片，手机端每行一张。
- 卡片显示序号、收藏按钮、日语、假名和中文翻译。
- 卡片避免不必要的大面积留白。
- 支持换一组和重新随机。

### 5.3 已学习过滤

背诵本和错题本中的词汇都视为已经学习过，不再进入普通学习分组。

### 5.4 默记模式

默记模式适用于学习页和词库页，默认关闭。

| 字段 | 进入默记模式时 | 单词级操作 |
|---|---|---|
| 日语 | 显示 | 点击后隐藏，再次点击显示 |
| 假名 | 隐藏 | 点击后显示，再次点击隐藏 |
| 翻译 | 隐藏 | 点击后显示，再次点击隐藏 |

- 普通模式下，日语、假名、翻译的顶部开关独立生效。
- 普通开关关闭后对应内容真正留空，不显示替代圆点。
- 默记模式开启时暂时禁用普通显示开关。
- 退出或重新进入默记模式时，单词级状态恢复默认值。

## 6. 测试

### 6.1 题型

每组词汇分别检测：

1. 根据日语选择假名。
2. 根据翻译选择日语。
3. 根据日语选择中文翻译。

### 6.2 出题规则

- 每题四个选项，只有一个正确答案。
- 单词顺序、题型顺序和选项顺序全部随机。
- 错误选项不得与正确答案重复。
- 答题后立即显示正确或错误反馈。
- 切题和按钮操作提供轻量动画。

### 6.3 结果

| 结果 | 保存位置 | 后续行为 |
|---|---|---|
| 三种检测全部通过 | 背诵本 | 不再进入待学习分组 |
| 任一题答错 | 错题本 | 可在复习页重新测试 |

## 7. 复习

### 7.1 布局

- 电脑端：左侧二级导航，右侧内容。
- 手机端：二级导航在上方，内容在下方。
- 错题、背诵和收藏使用紧凑卡片；电脑端双列，手机端单列。

### 7.2 页面内筛选

错题本、背诵本和收藏各自拥有词汇分类筛选：

- “全部”不限制类别。
- 指定类别只显示属于该类别的词汇。
- 筛选位于对应二级页面内部，不放在复习模块顶部。

### 7.3 错题本与背诵本

- 错题本显示答错词汇，并提供“复习全部”入口。
- 背诵本显示已经通过测试的词汇。
- 两个页面均支持收藏和取消收藏。

## 8. 收藏与收藏组

### 8.1 收藏组字段

| 字段 | 必填 | 规则 |
|---|---:|---|
| 名称 | 是 | 用户自定义，同一用户下不能重复 |
| 备注 | 否 | 描述复习范围或用途 |
| 默认组 | 是 | 每位用户始终保留一个默认组 |

### 8.2 业务规则

1. 首次使用时自动创建“默认收藏组”。
2. 新建或编辑收藏组时可以设为默认。
3. 设置新默认组后，原默认组自动取消默认。
4. 普通收藏按钮直接加入默认组，不弹出组选择。
5. 同一个词汇可以存在于多个收藏组。
6. 收藏提示必须显示实际收藏组名称。
7. 收藏页取消收藏时，只删除当前查看组中的记录。

### 8.3 收藏页面

- 支持切换、新建和编辑收藏组。
- 筛选项在左侧同一行显示，新建和“编辑当前组”操作在右侧并垂直居中。
- 支持编辑名称、备注和默认状态。
- 显示当前收藏组备注。
- 支持按词汇类别或“全部”筛选。
- 切换错题本、背诵本、收藏的类别或收藏组时显示 Loading 状态。

## 9. 词库

### 9.1 查询和分页

- 分类是查询表单的一部分，不显示重复的顶部分类切换。
- 支持日语、假名和翻译模糊查询。
- 查询前自动去掉关键词前后空格。
- 分页请求显示 Loading 动画。
- 翻页后平滑滚动到页面顶部。
- 默认每页 30 条，可选择 10、20、30、40、50、100。
- 显示当前页、总页数和总记录数。
- 支持输入页码后按回车或点击“跳转”，并将页码限制在有效范围内。
- 桌面表格列宽固定；显示或隐藏翻译时不得造成列宽跳动，标签和操作列保持紧凑。

### 9.2 数据维护

- 支持新增、编辑和删除词汇。
- 新增和编辑时可以选择多个类别。
- 假名为可选字段；词汇、固定搭配或句子没有可靠读音时允许留空。
- 不保存“熟悉度”或来源说明字段；来源文件与行号只保存在类别关联记录中。
- 每个词汇支持收藏和取消收藏。
- 桌面端收藏星标与日语词面使用左对齐 Flex 布局，上下居中，只保留少量间距且不得换行。
- 日语、假名、翻译内容使用普通文本元素呈现，仅在默记模式下获得切换交互。
- 支持独立隐藏日语、假名和翻译。
- 支持默记模式。

### 9.3 手机端

- 使用两层卡片布局：第一层两端对齐，左侧显示日语和可选假名，右侧显示收藏按钮；收藏按钮顶部对齐，长句只在左侧自然换行。
- 第二层显示中文翻译和全部标签；编辑、删除等操作按钮不在手机端显示。
- 默认隐藏标签、编辑和删除操作列。
- 列宽固定在视口内，长句和搭配自动换行，不产生横向滚动。

## 11. 管理

### 11.1 类别

- 不提供删除操作。

## 12. 公共交互

### 12.1 选词查询

- 仅在学习卡片、复习卡片和词库词汇行中选中非空文本后显示查询浮层；普通导航和文章不触发。
- 浮层优先显示在选区上方，上方空间不足时显示在选区下方；鼠标、触屏和键盘选取均须稳定触发。
- 选中内容严格为一个汉字时，显示“漢字ペディア”和“Weblio”两个按钮。
- 选中假名、多个汉字、词语、短语或句子时，只显示“Weblio”按钮。
- 点击按钮后将选中文本进行 URL 编码，在新窗口打开对应查询页面，并提供轻量按压反馈。
- 查询服务图标必须保存在项目本地，不得在页面运行时直接引用第三方图标 URL。

### 12.2 Notification

- 使用公共 Notification 组件。
- 位于页面右上角，浅绿色背景、深绿色文字。
- 单条默认显示 1 秒后消失。
- 多条消息从上向下堆叠并自动补位。
- 不阻挡页面点击。
- 收藏和取消收藏都使用该反馈。

### 12.3 动画

- 页面切换：淡入淡出。
- 答题：正确、错误和切题反馈。
- 分页：平滑滚动。
- Notification：快速淡入。
- 所有前端 HTTP 请求都显示统一、可见且不阻塞操作的 Loading 状态。
- 新增词汇、类别和收藏组提交后立即锁定提交按钮；请求完成前重复点击不得再次创建记录。
- 手机端编辑弹窗限制在可视高度内，弹窗内容可以纵向滚动，保存按钮必须可达。
- 系统启用“减少动画”时减少非必要动画。

### 12.4 GitHub 入口

- 页面右上角显示带背景的斜角三角入口，点击后在新窗口打开项目仓库。
- GitHub 图标保存为项目本地静态资源，不在运行时请求第三方图标。
- 鼠标悬停时提供轻量的猫尾摆动效果，键盘聚焦时保持清晰焦点样式。

## 13. 数据与安全规则

- 业务关联统一使用数据库 ID。
- 当前个人站点的进度、收藏组和收藏统一使用稳定的站点所有者标识，不得因请求是否带登录邮箱而拆成多个数据空间。
- 默认收藏组切换必须保证最终只有一个默认组。
- 删除词汇时同步清理其进度、类别关联和收藏。
- API 必须验证类别 ID、词汇 ID、收藏组归属和输入内容。
- 数据库凭据不得出现在浏览器、源码和 Git 历史中。
