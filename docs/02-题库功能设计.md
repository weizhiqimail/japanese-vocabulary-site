# 独立题库与连续做题功能改造方案

## 1. 方案结论

在完整保留现有日语词汇、语法、句子、集合、学习、复习和词汇测试功能的前提下，新增一个与“日语知识库”并列的“固定题库”业务域。

AWS 等习题不能作为词汇、语法或集合成员保存，也不能直接复用现有 `StudyModule`。当前测试从词汇动态生成选项，前端判断正误，后端只接收 `vocabularyId + correct`；新题库的题干、选项、答案和解析均为正式数据，必须由后端判题，并独立保存答题进度、作答流水、错题和收藏状态。

首期产品模型：

- 一个题库代表一套固定、有稳定顺序的题，例如“AWS SAA-C03（500 题）”。
- 第一次从第 1 题开始，每题提交后立即保存；做完 10 题退出，下次从第 11 题继续。
- 普通做题按导入顺序推进；错题练习和收藏练习不改变普通做题进度。
- 每次作答保留不可变历史；题目维度另存累计次数、错误次数和最近结果等汇总。
- 答错自动进入错题本；收藏由用户主动切换，两种状态相互独立。
- 网站不提供题目 CRUD，内容只通过受控导入脚本维护。

## 2. v2 现状与改造边界

本方案只以 `japanese-vocabulary-site-v2` 为依据：

- 前端为 `frontend/`：React、React Router、Chakra UI、Axios。
- 后端为 `backend/`：NestJS、TypeORM、MySQL、DTO 白名单校验和 Swagger。
- Vite 在开发时代理 `/api`；生产由 NestJS 同时提供 API 和 `backend/web` 中的 SPA。
- 所有业务 API 受会话 Cookie 保护。进度必须关联当前 `app_users.id`，即使目前是单用户系统也不应写成全局状态。
- 后端约定为 GET 查询、POST 写入，业务 ID 放 query/body，不使用 REST 路径参数。
- TypeORM `synchronize` 永久关闭；运行 schema 是 `backend/database/schema.sql`，文档副本是 `docs/schema.sql`。

可以复用 `AppLayout`、保护路由、Chakra 主题、通知、通用页面组件、Axios 封装、统一响应、事务和日志。不能复用：

- `collections`、`collection_vocabularies`：只能表达词汇集合。
- `study_events`：表达词汇学习/复习事件。
- `test_sessions`、`test_answers`：schema 虽有定义，但 v2 没有相应 Entity，当前业务也没有使用；语义仍面向词汇/语法动态测试。
- `StudyService.submitAnswer(vocabularyId, correct)`：信任前端的 `correct`，且只归集词汇错题，不适合固定题库。
- `ImportsModule`：用于词汇候选审核；题库导入无页面审核和 CRUD，应单独实现。

## 3. 首期范围

包含：多个题库、单选和多选、固定题干/选项/答案/解析、顺序做题、逐题保存、断点续做、后端判题、作答历史、错题、收藏、错题/收藏练习、题库统计、JSON 校验及幂等导入、响应式页面。

不包含：页面题目 CRUD、随机组卷、限时考试、及格线、AI 生成、间隔重复、题目讨论，以及把固定题库错题混入词汇错题集合。

## 4. 前端业务根路由与页面

前端不再把全部功能平铺在根路径下，而是明确划分三个业务根：

- `/words`：现有日语单词及知识学习业务。
- `/questions`：新题库及做题业务。
- `/account`：登录和以后可能增加的账户资料、会话管理。

应用根路径 `/` 根据登录状态重定向到 `/words` 或 `/account/login`。顶级导航显示“单词”“题库”“账户”，进入某个业务域后再显示该域的二级导航。这样未来题库扩展不会继续挤占单词导航。

### 4.1 现有路由迁移

| 当前路由 | 新路由 |
| --- | --- |
| `/login` | `/account/login` |
| `/` | `/words` |
| `/collections/**` | `/words/collections/**` |
| `/vocabularies/**` | `/words/vocabularies/**` |
| `/grammars/**` | `/words/grammars/**` |
| `/sentences/**` | `/words/sentences/**` |
| `/review/**` | `/words/review/**` |
| `/manage/**` | `/words/manage/**` |

为了兼容书签和 History 刷新，旧地址首期保留 `<Navigate replace>` 重定向到新地址，稳定一轮后再移除。`ProtectedRoute` 保护 `/words/*`、`/questions/*` 和账户内页，只有 `/account/login` 为公开页。

题库页面路由：

| 页面 | 路由 | 作用 |
| --- | --- | --- |
| 题库首页 | `/questions` | 大组/小组筛选、题库卡片和进度 |
| 分组浏览 | `/questions/groups/:groupCode` | 浏览 AWS 或其下 CLF 等组 |
| 题库详情 | `/questions/banks/:id` | 统计及练习入口 |
| 顺序做题 | `/questions/banks/:id/practice` | 从断点继续 |
| 错题练习 | `/questions/banks/:id/errors` | 只练当前错题 |
| 收藏练习 | `/questions/banks/:id/favorites` | 只练收藏题 |
| 作答历史 | `/questions/banks/:id/history` | 分页作答流水 |

页面继续置于 `ProtectedRoute` 和 `AppLayout` 内。

### 4.2 题库首页

顶部先展示大组（AWS），选中后展示小组（CLF），也允许通过 `groupId`、`subgroupId`、`q` 和分页参数直接筛选。每张题库卡片展示完整分组路径 `AWS / CLF`、考试代号 `CLF-C02`、题量、已完成数、剩余数、首次正确率、错题数、收藏数和最近作答时间。按钮按状态显示“开始做题”“继续做题（第 11 / 719 题）”或“查看结果”。首期不提供清空历史。

### 4.3 做题页

1. 服务端返回当前题，未提交前不返回正确选项和解析。
2. 单选直接选择；多选勾选后提交。
3. 服务端校验题库、题目和选项，并自行判分。
4. 同一事务写入流水、题目状态和主线进度。
5. 提交后显示正误、标准答案和完整解析，由用户点击“下一题”。
6. 刷新定位到第一道未提交题；重复提交不重复计数。
7. 最后一题完成后显示结果摘要。

手机端选项为整行可点击卡片，操作区可固定底部，不使用横向滚动表格；桌面端限制正文最大宽度。

页面同时展示题目、选项和解析中所有已有的语言版本，顺序为 English、中文、日本語；没有某种语言时只跳过该语言，不显示空占位。导入器同时兼容完整三语对象、部分语言对象和单字符串字段。

### 4.4 错题和收藏

- 答错自动进入错题并增加错误次数。
- 后续答对不自动移出；用户可主动标记已掌握，历史不删除。
- 已移出题再次答错会重新进入错题。
- 收藏切换不影响错题、进度或历史。
- 错题/收藏练习按原始顺序进行，首期不维护独立断点。
- 这些模式的作答计入历史与累计统计，但不推进主线。

## 5. 断点续做语义

断点必须由服务端保证，不能依赖前端页码或 `localStorage`：

- 每个 `user_id + bank_id` 只有一条主线进度。
- `current_question_id` 指向下一道未完成题，`current_position` 仅用于显示。
- 首次进入指向有效题中 `sort_order` 最小者。
- 只有 `mode = sequential` 且提交题正是当前题时才推进游标。
- 下一题由数据库计算，客户端不能指定新游标。
- `request_key` 保证网络重试幂等。
- 提交时锁定进度行；双标签页并发时先到者成功，后到者收到进度冲突。
- 完成后 `status = completed`、`current_question_id = NULL`。

不能只保存数字下标：题库更新或禁用题目后可能指错题。恢复时以稳定题目 ID 为准，位置只作展示与一致性检查。

## 6. 数据库设计

建议新增 8 张表。所有正式对象逻辑删除，外键只使用数据库 ID，Entity 配置和 schema 字段均带注释。

### 6.1 `question_groups`

用于题库的大小组层级，不把 AWS、CLF 等分组写成题目上的魔法字符串：

- 大组：`AWS`，`group_level = provider`，`parent_id = NULL`。
- 小组：`CLF`，`group_level = certification`，`parent_id = AWS.id`。
- 具体题库：`CLF-C02`，通过 `question_banks.group_id` 归属 CLF 小组。

字段为 `id`、`parent_id`、`code`、`name`、`group_level`、`description`、`sort_order`、`enabled`、维护时间和 `deleted_at`。同一父级下 `code` 唯一。首期只允许两层，但查询和数据结构允许以后增加 Azure、GCP 或 AWS 下的 SAA、SAP、DVA 等小组。

### 6.2 `question_banks`

`id`、`group_id`、唯一 `code`、`name`、`description`、`source`、`content_version`、`supported_languages` JSON、`default_language`、`question_count`、`enabled`、`created_at`、`updated_at`、`deleted_at`。本批数据的 `code` 为 `aws-clf-c02`，分组链为 `AWS / CLF`。

### 6.3 `questions`

`id`、`bank_id`、`external_key`、`sort_order`、`topic_code`、`question_type`、`question_texts` JSON、`rationale_texts` JSON、`source_explanation_texts` JSON、`answer_confidence`、`community_conflict`、`rationale_note`、`content_hash`、`enabled` 和维护时间。`*_texts` 原样保存 `{ en, zh, ja }`，避免三语错位。题型枚举为 `single_choice`、`multiple_choice`，预留 `true_false`。

唯一约束：`(bank_id, external_key)`、`(bank_id, sort_order)`。

### 6.4 `question_options`

`id`、`question_id`、`option_key`、`content_texts` JSON、`is_correct`、`sort_order`。`content_texts` 保存 `{ en, zh, ja }`；`is_correct` 只能由后端判题读取。

唯一约束：`(question_id, option_key)`、`(question_id, sort_order)`。答案由正确选项集合表达，不另存容易漂移的答案文本。

### 6.5 `question_progress`

每个用户每个题库一条：`id`、`user_id`、`bank_id`、`status`、`current_question_id`、`current_position`、`answered_count`、`correct_count`、`started_at`、`last_answered_at`、`completed_at`、`updated_at`。

状态为 `not_started`、`in_progress`、`completed`；唯一约束为 `(user_id, bank_id)`。

### 6.6 `question_attempts`

不可变作答流水：`id`、唯一 `request_key`、`user_id`、`bank_id`、`question_id`、`mode`、`selected_option_keys` JSON、`correct_option_keys` JSON、`is_correct`、`duration_ms`、`answered_at`。

模式为 `sequential`、`error_review`、`favorite_review`。多选采用集合完全相等判定，不比较顺序，首期无部分得分。

### 6.7 `question_states`

每个用户每题一条，主键 `(user_id, question_id)`。保存：

- `attempt_count`、`correct_count`、`wrong_count`
- `last_is_correct`、`last_answered_at`
- `first_wrong_at`、`last_wrong_at`
- `is_in_error_book`、`error_resolved_at`
- `is_favorite`、`favorited_at`

`question_attempts` 是事实来源；`question_progress` 和 `question_states` 是查询汇总，答题时三者在同一事务更新。

### 6.8 `question_import_batches`

记录题库 ID、内容版本、文件名、文件 SHA-256、题数、状态、校验/差异摘要及开始和完成时间，不与词汇 `import_batches` 混用。

### 6.9 结构同步清单

实现时必须同时更新：

1. `backend/database/schema.sql`
2. `docs/schema.sql`
3. `backend/src/entities/**` 和 `ALL_ENTITIES`
4. `docs/04-数据库设计.md`
5. `docs/03-应用架构与接口规范.md`

不得开启 TypeORM `synchronize`，不得把数据库全量同步加入 build、启动或部署。

## 7. 现有 AWS 数据与导入方案

### 7.1 已处理文件分析

数据来源目录为：

```text
D:\program\computer-science-knowledge\AWS\ExamAWSCertifiedCloudPractitionerCLF-C02
```

导入时忽略全部 PDF。该目录中的主要结构化文件为：

- `AWS_CLF_C02_questions.json`：英文原始题目、选项、答案、投票和评论。
- `AWS_CLF_C02_questions_trilingual.json`：中英日对齐题目，作为首选导入源。
- `AWS_CLF_C02_analysis_report.md`：题数、答案核验和争议题说明，仅用于导入报告参考。
- `.clf_c02_translation_cache.json`、raw 文本：处理过程数据，不作为正式导入源。

三语 JSON 的实际情况：

- 题目总数 719。
- 633 道单选，86 道多选。
- `id` 为 1–719，可直接作为 `external_key` 和初始 `sort_order`。
- `question`、每个 `options` 值、`answer_review.rationale`、`source_explanation` 都是 `{ en, zh, ja }`。
- `option_order` 明确保存选项顺序。
- `answer_review.reviewed_answer` 是字符串：单选如 `"C"`，多选如 `"AE"`，不是数组。
- `topic` 当前 719 题均为 `1`，不能把它误当成 AWS/CLF 分组；先保存为 `topic_code`，以后获得真实领域分类时再扩展。
- 另有 `confidence`、`community_conflict`、投票和评论等来源元数据。

正式导入优先采用 `reviewed_answer`，同时保留 `source_answer`、置信度和争议标记用于审计。`comments` 和 `vote_distribution` 数据量大、不是做题闭环必需，首期不拆表导入；原始 JSON 及文件哈希作为审计来源。若页面以后需要社区信息，再增加独立来源数据表，不能塞入解析正文。

### 7.2 直接支持现有 JSON

导入器直接读取现有三语格式，不要求预先转换：

```json
{
  "exam": "AWS Certified Cloud Practitioner CLF-C02",
  "languages": ["en", "zh", "ja"],
  "total_questions": 719,
  "questions": [
    {
      "id": 9,
      "topic": 1,
      "question": { "en": "...", "zh": "...", "ja": "..." },
      "options": {
        "A": { "en": "...", "zh": "...", "ja": "..." },
        "E": { "en": "...", "zh": "...", "ja": "..." }
      },
      "option_order": ["A", "B", "C", "D", "E"],
      "answer_review": {
        "source_answer": "AE",
        "reviewed_answer": "AE",
        "confidence": "high",
        "community_conflict": false,
        "rationale": { "en": "...", "zh": "...", "ja": "..." }
      }
    }
  ]
}
```

导入参数显式提供分组和题库标识：`--group AWS --subgroup CLF --bank CLF-C02`。这样来源文件的 `exam` 只作为校验和显示依据，不能隐式制造重复分组。

### 7.3 命令与导入规则

建议增加：

```text
backend/scripts/validate-question-bank.mjs
backend/scripts/import-question-bank.mjs
npm run questions:validate -- --file "D:\...\AWS_CLF_C02_questions_trilingual.json"
npm run questions:import -- --file "D:\...\AWS_CLF_C02_questions_trilingual.json" --group AWS --subgroup CLF --bank CLF-C02 --dry-run
npm run questions:import -- --file "D:\...\AWS_CLF_C02_questions_trilingual.json" --group AWS --subgroup CLF --bank CLF-C02
npm run questions:verify
```

脚本复用 v2 的环境规则：本地读取 `backend/.env.local`，生产读取 `backend/.env.production`，并兼容 URL 或分项数据库配置。

导入分三步：

1. 校验顶层题数、题号/顺序/选项键唯一性、每个题干和选项至少具有一种非空语言，以及答案字母都存在于 `option_order`。
2. 将 `reviewed_answer` 拆成去重字母集合；长度为 1 判定 `single_choice`，长度大于 1 判定 `multiple_choice`。不能依赖题干中的 “Choose two”。
3. dry-run 列出新增、不变、内容变化、答案变化、顺序变化、缺失题目、低置信度和社区争议题。
4. 按 `bank.code + externalKey` 幂等导入；相同哈希跳过，成功后更新题数和批次。

已开始题库默认禁止改变已有 `sort_order`；文件中消失的题默认阻止导入，只能显式逻辑禁用。允许修正文案、解析或答案，但答案变化必须醒目提示，历史答案快照不重算。

## 8. 后端业务根路由与 API

后端同样划分三个顶级模块和 Controller 前缀：

- `/api/words/*`：现有词汇、语法、句子、集合、学习、复习、词汇导入和设置。
- `/api/questions/*`：分组、题库、做题、错题、收藏和历史。
- `/api/account/*`：登录、退出、当前用户和以后可能增加的账户功能。

迁移期间，现有 `/api/auth/*`、`/api/study/*`、`/api/vocabularies/*` 等旧接口可以由兼容 Controller 转发或暂时保留，前端先统一改用新前缀；兼容层不得复制业务逻辑。

题库 API 遵循 v2 的 GET 查询、POST 写入、无 API 路径参数约定：

| 方法与地址 | 参数 | 用途 |
| --- | --- | --- |
| `GET /api/questions/groups` | `parentId,level,q` | 查询 AWS 等大组或 CLF 等小组 |
| `GET /api/questions/banks` | `groupId,subgroupId,pageNum,pageSize,q` | 题库列表及用户进度 |
| `GET /api/questions/banks/detail` | `bankId` | 详情、分组路径和统计 |
| `GET /api/questions/practice/current` | `bankId,mode` | 当前题的全部可用语言，不含答案解析 |
| `GET /api/questions/items` | `bankId,scope,pageNum,pageSize,q` | 错题/收藏列表 |
| `GET /api/questions/attempts` | `bankId,pageNum,pageSize` | 作答历史 |
| `POST /api/questions/attempts/answer` | 专用 DTO | 服务端判题并推进进度 |
| `POST /api/questions/states/save` | 专用 DTO | 收藏切换或移出错题 |

提交 DTO：

```json
{
  "requestKey": "3f76d151-44f8-4fb6-a8ad-cc871f118770",
  "bankId": 1,
  "questionId": 123,
  "mode": "sequential",
  "selectedOptionKeys": ["B"],
  "durationMs": 42000
}
```

后端从会话取得 `userId`，绝不接收客户端的 `userId` 或 `correct`。它还要验证题目归属、有效状态、选项键和主线当前位置。新增 DTO 契约同步到 `docs/API_PARAMETER_CONTRACTS.md`。分页仍只允许 10、20、30、50、100。

## 9. v2 模块重组

根 `BusinessModules` 只聚合三个业务域模块，每个域内部再组合子模块：

```text
BusinessModules
├─ WordsModule
│  ├─ KnowledgeResourcesModule
│  ├─ StudyModule
│  ├─ ImportsModule
│  ├─ SettingsModule
│  └─ WordsDashboardModule
├─ QuestionsModule
│  ├─ QuestionGroupsModule
│  ├─ QuestionBanksModule
│  ├─ QuestionPracticeModule
│  └─ QuestionImportService（脚本复用，不开放管理页面）
└─ AccountModule
   └─ AuthModule
```

这一步是路由和模块边界重组，不应同时重写现有词汇业务实现。原 Service 和 Entity 保持职责，通过模块重新导入；旧 API 兼容层在迁移期单独存在。

题库不是日语 `KnowledgeResourcesModule` 的子资源，其代码结构为：

```text
backend/src/
  entities/question-bank/
  entities/question-group/
```

## 10. 一致性、安全和日志

- API 继续由 Cookie Guard 保护，所有用户状态查询必须带当前 `user_id`。
- 提交答案时对进度行加悲观写锁；首题安全创建进度记录。
- `request_key` 建唯一索引，重试返回首次结果。
- 并发提交的第二个非幂等请求返回进度冲突。
- 题目 Entity 不直接序列化给前端，使用响应 DTO 防止 `isCorrect` 泄露。
- 题干、选项、解析首期按纯文本渲染；未来支持 Markdown 时必须清洗 HTML。
- 日志只记 ID、模式、数量和结果，不记录完整题干、用户答案或 Cookie。
- 全局 DTO 白名单继续生效。

## 11. 统计口径

- 主线已完成数：顺序模式已提交的不同题目数。
- 首次正确率：顺序模式首次作答正确题数 / 主线已完成题数。
- 累计正确率：用户所有模式正确次数 / 所有作答次数。
- 错题数：当前 `is_in_error_book = 1` 的有效题数。
- 收藏数：当前 `is_favorite = 1` 的有效题数。
- 剩余数：有效题目总数 - 主线已完成数。

统计由服务端聚合，前端不自行拼算。

## 13. 验收标准

- `/`、旧词汇路由和旧 API 在迁移期能正确跳转或兼容；新业务分别位于 `/words`、`/questions`、`/account` 和对应 `/api` 前缀下。
- AWS 大组下可查询 CLF 小组，CLF 下可查询 CLF-C02 题库；分组筛选不会依赖题目 `topic = 1`。
- 三语 JSON 导入结果恰好为 719 题，其中 633 道单选、86 道多选；多选字符串 `AE` 正确解析为选项集合 `[A,E]`。
- CLF-C02 的 719 题首次显示第 1 题；提交 10 题退出或刷新后显示第 11 题。
- 错题/收藏练习不改变主线，最后一题后不出现第 501 题。
- 相同 `requestKey` 不重复写入；双标签页不能重复推进。
- 单选唯一正确才判对；多选必须与答案集合完全一致。
- 客户端伪造 `correct`、`userId` 或额外字段不能影响结果。
- 未提交前不返回正确选项和解析；每次有效作答保留答案快照。
- 答错立即进错题；答对不自动移出；移出后再次答错会重新进入。
- 收藏切换不影响错题、主线或历史，一次操作只显示一条 2 秒通知。
- 重复导入不产生重复题，不重置用户进度。
- 顺序变化、题目缺失和答案变化在导入时受到保护或醒目提示。
- 原有日语功能无回归；两个 schema、Entity 和文档一致；`synchronize` 保持 `false`。
- 桌面和移动端符合 Chakra UI 及响应式规范，三个 build 全部通过。

## 14. 风险与后续

主要风险是题目版权、题库更新破坏顺序、答案修订影响旧统计，以及接口泄露答案。通过授权确认、稳定题号、内容版本、答案快照、更新保护和专用响应 DTO 分别控制。

首期稳定后可增加随机练习、分类练习、未做题练习、错误次数排序、限时模拟考试、独立考试会话、题目笔记和版本对比。这些能力继续建立在独立题库及不可变作答流水之上，不修改词汇领域的数据语义。
